# Changelog

## RFC-009 mic pipeline fix
- Fixed a real-hardware bug found on a Windows 11 target machine: `record_from_microphone` asked PortAudio to open the input device directly in the 1-channel/16 kHz format STT and speaker verification need. On that machine's built-in "Microphone Array", this silently returned near-silent audio (amplitude ~1e-4) instead of failing loudly, which made `voice enroll`'s speaker embedding step operate on effectively empty audio; a separate WASAPI-variant device index for the same physical hardware rejected that format outright ("Invalid number of channels" / "Incompatible host API specific stream info").
- `record_from_microphone` now always records at the input device's own native sample rate/channel count (confirmed via real-device diagnostics to return real signal, e.g. RMS ~0.047 instead of ~0.0002) and downmixes to mono (channel average) and resamples to 16 kHz in software afterward, reusing the existing `resample_audio` helper already used for the phone/`/voice/turn` path. It never again asks PortAudio itself to capture directly in the target STT/verification format.
- Added `voice_input_device` (default `1`), `voice_input_sample_rate` (default `44100`), and `voice_input_channels` (default `4`) to the runtime configuration allowlist, so a different machine's native mic format/device index can be set via `config set` without a code change. `voice_input_device` explicitly allows `0` (a valid PortAudio device index), unlike most other integer `voice_*`/numeric settings which treat `0` as invalid.
- Recording failures now log the selected device index/format and raise a `VoiceCaptureError` naming that device, instead of a generic "Microphone recording failed." message, so a misconfigured or WASAPI-only device index is diagnosable from `voice enroll`'s own error text.
- Added regression tests: native device/rate/channel settings are actually passed to `sounddevice.rec`, a multi-channel constant signal survives downmix+resample as the same value at the target sample count, and a recording failure's error message names the failing device index. Full test suite re-run after the fix (see PR).

## RFC-009
- Added on-demand voice input/output: local speech-to-text (`faster-whisper`), local text-to-speech (Piper), and local owner speaker verification (SpeechBrain ECAPA-TDNN) before any utterance is treated as input at all. A voice transcript is handed to the exact same `app.brain.router.route_command` text-intake path a typed message uses, so it carries no special authority — risk classification and `approve plan` apply identically to voice and typed input, and free-form spoken "remember" phrasing works via the existing `memory.remember` AI tool with no new memory code.
- Speaker verification runs before transcription: a voice that does not match the enrolled owner's stored embedding is rejected with no transcript ever produced, not merely discarded afterward, satisfying RFC-009's hard boundary that only the enrolled owner's voice is ever processed. Enrollment is closed-set and opt-in (`voice enroll`, banking one local-mic sample per call and averaging into a single embedding after `MIN_ENROLLMENT_SAMPLES`; `voice forget me`, routed through the same confirmation flow as destructive power actions), mirroring the face-enrollment shape already described as a permanent decision in `docs/VISION_ROADMAP.md`. No raw audio is ever persisted — only the derived embedding (`data/voice_profile.json`).
- Fixed a pre-existing gap: `voice_on()`/`voice_off()` previously only flipped an in-memory flag disconnected from the `voice_enabled` config key (unlike `ai on`/`ai off`, which correctly call `set_runtime_config_value`). They now follow the same pattern.
- Added `voice enroll`, `cancel voice enrollment`, `voice forget me`/`confirm voice forget me`, and `voice talk` (local-mic push-to-talk) deterministic commands, and enriched `voice status` to report enabled/mic-active/enrolled state, mirroring `vision status`/`location status`.
- Added the phone-facing transport: `POST /voice/turn` (one WAV recording in, JSON with transcript/reply text/base64 WAV reply out) and `GET /voice/client` (a minimal push-to-talk PWA page, capturing raw PCM via the Web Audio API and encoding to WAV in-browser rather than relying on `MediaRecorder`'s compressed webm/opus, so the server needs no audio-transcoding dependency). Both share RFC-010's existing Tailscale-bound HTTP listener and its `location_bind_host`/`location_port`/`location_shared_secret` rather than opening a second listener — `app/brain/location/server.py` was generalized from an Overland-specific handler into a small path-registry dispatcher (`register_route`/`register_get_route`) to support this, without changing `/location/overland`'s own behavior or its existing tests.
- Visible mic-active state (mirroring the camera-state visibility already promised for RFC-007D): `voice status`'s mic-active flag is true only for the exact duration audio is being captured for one turn, never a state where JARVIS is listening without it being reflected in status.
- New dependencies: `faster-whisper`, `piper-tts`, `speechbrain`, `torchaudio`, `sounddevice`. Resemblyzer was evaluated first for speaker verification but dropped — its hard dependency on `webrtcvad` has no prebuilt Windows wheel for this project's Python version and needs a C compiler unavailable in the target environment; SpeechBrain's ECAPA-TDNN avoids that dependency chain entirely.
- Added `voice_stt_model`, `voice_tts_voice`, and `voice_verification_threshold` to the runtime configuration allowlist (`voice_enabled` already existed).
- Deliberately out of scope for this version (documented in `docs/RFC-009_ON_DEMAND_VOICE_ASSISTANT.md`, not silently assumed solved): wake-word detection (push-to-talk only for now) and anti-replay/liveness detection.

## RFC-010
- Added phone location and turn-by-turn navigation over Tailscale: a `/location/overland` HTTP route (bound only to the configured `location_bind_host` Tailscale interface IP, never `0.0.0.0`; fails to start with a clear error rather than silently falling back to a public bind) that ingests Overland's GeoJSON POST format, authenticated by an `Authorization: Bearer <location_shared_secret>` token checked against Overland's own access-token field. A rejected POST is logged via `record_audit_event` and never updates stored state.
- Only the single freshest GPS point per device is ever stored — each new post overwrites the previous one, never appended to a history, in a new `app/brain/location/state.py` module following the same dataclass + module-level singleton + `RLock` pattern as `app/brain/vision/state.py` and `app/brain/browser/state.py`.
- Added AI tools `location.where_am_i` (reverse-geocodes the freshest point via Nominatim, LOW risk), `location.distance_to` (haversine distance to an owner-saved place, LOW risk, no network call), `location.save_place` (persists a named place's coordinates to `data/places.json`, MEDIUM/`persistent_write` risk mirroring `memory.remember`'s tier exactly, including its exclusion from every project-scoping exemption so it never auto-executes), `navigation.start`/`navigation.get_next_instruction`/`navigation.stop` (OSRM-backed turn-by-turn sessions, LOW risk). `location.receive_overland_point` (the HTTP ingestion path) is deliberately *not* registered as an AI-callable tool, so a compromised or malfunctioning agent plan can never inject a fake location point.
- Routing is behind a small `RoutingProvider` interface (`app/brain/location/routing.py`) defaulting to the public OSRM demo server (`osrm_base_url`, swappable to a self-hosted instance without touching the tool surface); geocoding uses the public Nominatim service. Both use `urllib.request` only, matching this project's existing zero-new-dependency HTTP client convention (`app/brain/vision/ollama_provider.py`, `app/brain/ai/ollama_provider.py`) — no `requests`/`flask` dependency added; the inbound listener uses Python's stdlib `http.server.ThreadingHTTPServer`.
- **Capture/session lifecycle**: a `navigation.start` session is request/task-scoped exactly like an RFC-007B/RFC-007C Vision capture, and is deleted on task completion, failure, cancellation, *and* approval expiration — all four paths have a regression test. This matters because RFC-007B and RFC-007C's own capture-cleanup wiring were each independently discovered to be missing from `app.brain.planner.approval`'s approval-expiration path (a structurally separate "cancel a pending task" code path from `AgentController.cancel_pending_or_running_task`) after already being fixed once for `AgentController` alone. RFC-010's navigation-session cleanup helper is wired into both places — `AgentController` (task completion, both failure paths, and cancellation while pending/running) and `app.brain.planner.approval._synchronize_terminal_pending_state_locked` (approval expiration) — from the start, so this class of gap isn't repeated a third time.
- Added `location_enabled`, `location_bind_host`, `location_port`, `location_stale_after_seconds`, and `osrm_base_url` to the runtime configuration allowlist. `location_shared_secret` is deliberately excluded from that allowlist (and from `config show`/`config get`, which now redact it) since it is a credential, not a tunable setting — it is set once by editing `config/config.json` directly.
- Added deterministic `location status` / `navigation status` commands, mirroring `vision browser status`/`desktop captures`.

## RFC-007C
- Added one-shot desktop and window capture: `desktop.list_windows`, `desktop.capture_screen`, `desktop.capture_window`, and `vision.describe_desktop_capture`/`extract_text_from_desktop_capture`/`find_visual_element_in_desktop_capture`, mirroring the RFC-007B browser-capture shape (opaque `capture_id`, private TTL-bound store, no verification pipeline since a desktop capture has no DOM to check against).
- `desktop.capture_screen` and `desktop.capture_window` are always MEDIUM risk and are deliberately excluded from every project-scoping exemption in the risk analyzer, so they can never auto-execute even with `developer_mode` and `auto_execute_medium_project` both enabled. Added a regression test proving this explicitly.
- Enforced "one-shot" as a real limit, not just a description: added `MAX_DESKTOP_CAPTURES_PER_PLAN` (currently `1`), mirroring the existing `MAX_MEMORY_READS` plan-validator pattern, capping `desktop.capture_screen`/`desktop.capture_window` combined per plan.
- `desktop.capture_window` revalidates the target window immediately before capturing: existence, visibility, and title. Windows can reuse a closed window's handle for an unrelated window, so the title check specifically catches a plan being executed against a different window than the one the user approved, rejecting the capture with a clear reason instead of silently capturing the wrong thing.
- Added a deterministic `planner_v2.py` trigger for "screenshot/capture the desktop" and "screenshot/capture window `<title>`", resolving the window title against currently open windows at plan-construction time so the approval preview names the real window, not a placeholder.
- Implemented capture with zero new dependencies: Pillow's `ImageGrab` (already a dependency) plus `ctypes` calls into `user32.dll`/`dwmapi.dll` for window enumeration and rectangles, matching this codebase's existing `ctypes`-based Windows API style. Windows-only; fails explicitly and cleanly on other platforms.
- Added `vision_desktop_capture_enabled`, `vision_desktop_capture_ttl_seconds`, `vision_desktop_capture_max_bytes`, `vision_desktop_capture_max_width`, `vision_desktop_capture_max_height`, and `vision_desktop_capture_max_pixels` to the runtime configuration allowlist.

## Bug fix: config set discarding session-only toggles
- Fixed `config_set()` in `app/brain/configuration/config_commands.py` silently disabling any active session-only setting (`ai on`, `voice on`, `developer mode on`, `conversation on`, etc.) whenever an unrelated `config set <key> <value>` command ran. The cause: `config_set()` rebuilt the in-memory runtime snapshot from the just-reloaded config file alone, discarding whatever session-only overrides were layered on top of it.
- `config_set()` now captures the current effective runtime config (file plus active session overrides) before writing, patches in only the newly persisted key, and installs that merged result as the new snapshot. Every other active session-only override now survives an unrelated `config set` call, and a `config set` on a key that itself has a stale session override still ends up with the newly persisted value. `config_reset()` and `config_reload()` are unchanged; they still intentionally wipe the session snapshot.

- Added `memory_max_entries` and `memory_learned_capture_enabled` to the runtime configuration allowlist.
